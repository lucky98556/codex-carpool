# CPA 插件面板样式隔离规范

## 硬性原则

1. CPA 页面是“不可信宿主样式环境”。不能假设宿主没有 `button`、`input`、`dialog`、`header`、`footer`、`.form` 等全局规则。
2. 插件页内组件必须以 `.cc-panel` 为作用域；进入浏览器顶层的原生 `<dialog>` 必须以唯一 ID 为根选择器，不能只依赖 `.cc-panel dialog`。
3. 不能使用会破坏继承、可访问性或主题变量的 `all: initial`。只对已确认会冲突的布局关键属性使用高特异性或 `!important`。
4. 操作按钮必须在静态 HTML 中占位。禁止为了补按钮在运行时向标题区追加 DOM，避免加载后二次排版和位置跳动。
5. 新弹窗必须把根节点、`[open]`、`::backdrop`、头部、滚动内容区、底部操作区、按钮和输入控件全部纳入独立样式守卫。
6. 颜色继续跟随 CPA 的明暗主题变量；布局、尺寸、间距和交互状态由插件自己控制。

## 实现检查

- 页面内选择器使用 `.cc-panel .component-name`，不要写裸 `button`、`table`、`.form` 作为新增规则。
- 顶层弹窗使用 `#dialog-id`、`#dialog-id>header`、`#dialog-id>.form`、`#dialog-id>footer` 等独立选择器。
- 表格、搜索框、按钮、状态、选中态分别检查浅色和深色主题。
- 中英文切换后重新检查按钮宽度、表头、弹窗标题和帮助文案，不允许依赖中文长度凑布局。
- 响应式只改变布局，不隐藏关键操作或完整数据入口。
- 预览页只能辅助调样式；最终必须验证 `panelHTML()` 组装出的生产面板和实际 CPA 页面。

## 回归要求

- 新增弹窗时，在面板静态测试中加入根选择器、头部、内容区和底部操作区守卫。
- 运行 JavaScript 语法检查、Go 单元测试和 `git diff --check`。
- 实际 CPA 环境至少验证浅色、深色两种主题；检查初次加载、刷新、打开弹窗和切换语言时是否发生样式闪烁或位置跳动。
- 若宿主仍能覆盖组件，先记录冲突选择器，再对最小范围属性增强特异性；不要扩大到全页重置。
